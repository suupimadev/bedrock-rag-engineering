# ルーブリック評価基準(人手評価用)

ルーブリック問題(`questions.json` で `category: "rubric"` の8問)の回答は、
LLM-as-judgeは使わず、以下の3軸・5段階で人間が評価する。

## 評価軸

### 正確性 (accuracy)
技術的な内容に誤りがないか。

| 点数 | 基準 |
|---|---|
| 5 | 誤りがなく、専門的に見ても正確 |
| 4 | 軽微な誤りや曖昧な表現が1つある程度 |
| 3 | 一部に誤りがあるが、全体の論旨は破綻していない |
| 2 | 複数の誤りがあり、信頼性に欠ける |
| 1 | 内容の大部分が誤っている |

### 網羅性 (completeness)
質問が求めている要素(例: 「3つ挙げて」なら3つ)を満たしているか。

| 点数 | 基準 |
|---|---|
| 5 | 求められた要素を過不足なく網羅している |
| 4 | ほぼ網羅しているが、1点程度不足 |
| 3 | 半分程度は網羅できている |
| 2 | 一部しか触れられていない |
| 1 | ほとんど要件を満たしていない |

### わかりやすさ (clarity)
初心者が読んでも理解しやすい説明になっているか。

| 点数 | 基準 |
|---|---|
| 5 | 専門用語に説明があり、例え話などで直感的に理解できる |
| 4 | おおむね分かりやすいが、一部専門用語の説明が不足 |
| 3 | 内容は正しいが、説明が専門的すぎる、または冗長 |
| 2 | 構成が分かりにくく、理解に時間がかかる |
| 1 | 文章として読みづらい、または論理展開が破綻している |

## 評価方法

1. `evaluation.runner` の実行で生成される `results/eval_*_records.csv` のうち、
   `category` が `rubric` の行を対象にする。
2. 各行の `rubric_accuracy` / `rubric_completeness` / `rubric_clarity` 列に、
   上記基準で1〜5の整数を手動で記入する(採点していない行は空欄のままでよい)。
3. 採点済みのCSVを `python -m evaluation.runner --aggregate-rubric <CSVパス>` に渡すと、
   モデルごとの平均スコアを集計できる。

## 注意点(記事に明記すること)

- この採点は人間による主観評価であり、LLM-as-judgeは使用していない。
- 採点者は1名のみであり、複数人によるクロスチェックは行っていない。評価にブレが存在しうる。
- 客観問題(`category: "objective"`)はこの採点の対象外(自動採点のみ)。
